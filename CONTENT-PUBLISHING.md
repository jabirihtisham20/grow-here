# Publishing blog content

Keystatic and the website use the same files in this repository. The four collections write `.mdx` entries to `content/grow/`, `content/space/`, `content/energy/`, and `content/life/`. The title field generates the entry filename/URL slug; the frontend treats that filename as authoritative. Featured and inline MDX image uploads are committed under `public/images/posts/` and referenced with `/images/posts/...` paths.

The frontend reads those files with `lib/posts.ts` during the Next.js build. Published entries appear at `/blog` and `/blog/<slug>` and in the sitemap, RSS feed, category pages, and search index. Draft entries are excluded from public pages. A commit that edits, publishes, or removes an entry changes the next build's content. This is build-time generation, not live revalidation.

## Production setup

The Keystatic config switches to GitHub storage in production and targets `jabirihtisham20/grow-here` by default. The Vercel project must be connected to that GitHub repository, have Git deployments enabled, and use the same production branch selected in Keystatic (this repository's current branch is `main`). Keystatic commits to other branches do not change production until that branch is merged into Vercel's production branch. Commits to the connected production branch trigger a Vercel build; the new deployment serves additions, edits, and deletions. Confirm the Git integration and production branch in Vercel before relying on automatic updates.

Configure these values in Vercel for the Production environment:

- `KEYSTATIC_GITHUB_CLIENT_ID`, `KEYSTATIC_GITHUB_CLIENT_SECRET`, `KEYSTATIC_SECRET`, and `NEXT_PUBLIC_KEYSTATIC_GITHUB_APP_SLUG`: generate them with Keystatic's GitHub mode setup and install the GitHub App with write access to this repository.
- `NEXT_PUBLIC_KEYSTATIC_GITHUB_REPO_OWNER` and `NEXT_PUBLIC_KEYSTATIC_GITHUB_REPO_NAME`: optional overrides; defaults are `jabirihtisham20` and `grow-here`.
- `NEXT_PUBLIC_SITE_URL`: canonical production origin, currently `https://growhere.online`.

Local development uses filesystem storage by default. Set `NEXT_PUBLIC_KEYSTATIC_STORAGE=github` only when you intentionally want local Keystatic to write through GitHub mode. Do not commit credentials; `.env.local` is ignored by Git. See `.env.example` for the variable names.

Slugs are generated by Keystatic's slug field and become the public `/blog/<slug>` route, so keep them unique across all four collections. The build rejects duplicate published slugs instead of rendering the wrong article. The older `/<category>/<slug>` routes remain available for existing links, while canonical metadata and generated links use `/blog/<slug>`.

For the production GitHub App, register `https://growhere.online/api/keystatic/github/oauth/callback` as a callback URL. Keystatic's GitHub sign-in uses this API route.
